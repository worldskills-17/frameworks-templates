# Next.js + Prisma Template

Next.js 16 (App Router, React 19) with Prisma ORM 7 + MySQL or PostgreSQL for WorldSkills UK competitions. Runs as a Node server (`next start`) on port 80 so server components and API routes can reach the database.

## Local development

```bash
npm install
npx prisma generate
DATABASE_URL="mysql://user:pass@localhost:3306/dev" npx prisma db push
DATABASE_URL="mysql://user:pass@localhost:3306/dev" npm run dev
```

`DATABASE_URL` can also go in a `.env` file: `prisma.config.ts` loads it for the Prisma CLI and Next.js loads it for the app.

## Production build

```bash
npx prisma generate
npm run build
npx prisma db push
npm run start
```

## Container build (CI)

Triggered automatically on push to `main` via Gitea Actions. DB credentials come from repository secrets (`DB_HOST`, `DB_NAME`, `DB_USERNAME`, `DB_PASSWORD`) and are baked into `DATABASE_URL` at build time. On every start the container runs `prisma db push` to apply the schema, then runs the seed command if one is configured and the seed files changed since the last start (a change resets the database first).

## Seeding

Set the seed command in `prisma.config.ts` (`migrations.seed`), for example `seed: 'node prisma/seed.mjs'` to use the included example. Run it locally with `npm run db:seed`. Prisma 7 ignores a `"prisma": { "seed": ... }` section in `package.json`.

## Endpoints

- `GET /` — landing page
- `GET /api/users` — list users (Prisma)
- `POST /api/users` — create a user (JSON body: `{ "email": "...", "name": "..." }`)

## Prisma 7 notes

- The connection URL is set in `prisma.config.ts`, not in the `datasource` block of `schema.prisma`.
- The client is generated by the `prisma-client` generator into `src/generated/prisma` (not into `node_modules`). Import it from there, not from `@prisma/client`. Run `npx prisma generate` after every schema change: `prisma db push` no longer runs it.
- Every database needs a driver adapter. `src/lib/prisma.js` picks it from the `DATABASE_URL` scheme: `@prisma/adapter-pg` for `postgresql://`, `@prisma/adapter-mariadb` (MySQL as well as MariaDB) for `mysql://`. The platform sets the matching `provider` in `prisma/schema.prisma` when the repository is created.
- The generated client is TypeScript. Next.js compiles it; plain Node scripts such as `prisma/seed.mjs` load it directly (Node 22.18+ runs TypeScript without a build step).

## Note on MySQL, MariaDB and PostgreSQL

The competition database server is MySQL 8.4. Prisma uses `provider = "mysql"` for both MySQL and MariaDB, so the schema is unchanged. `src/lib/prisma.js` adds `allowPublicKeyRetrieval=true` to the driver connection (MySQL 8 `caching_sha2_password` authentication without TLS) and caps the pool at `connectionLimit=5`, because the database server is shared. On PostgreSQL the `pg` pool is capped at 5 connections for the same reason.
